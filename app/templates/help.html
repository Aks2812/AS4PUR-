How {{ app_name }} works

What this tool does

{{ app_name }} wraps three Netskope administration tasks that used to require running scripts by hand on a laptop, so they can be run from a browser instead: importing Private App Segments in bulk, creating access policies for a list of users, and (for tenants with no Entra ID/SCIM sync of their own) creating local users and groups.

Every tenant and token is entered fresh, every time

No tenant settings or credentials are stored in this app. Each time you run an operation you provide the tenant name and an API token scoped for that operation. The token is used only for the duration of that run and is never saved anywhere - not to disk, not to the database, not to any log line. Logging out, or letting your session sit idle until it expires, clears it completely; you'll enter it again next time. The tenant name is not kept as a setting or a default either, but it is recorded in the audit history and job records of each run (see below), so you can tell which tenant a run was against.

Review before you commit

Every operation always shows a full review page first - what will be created, what will be skipped because it already exists, and what looks invalid - before anything is actually sent to Netskope. You have to explicitly confirm you've reviewed it before the final action becomes available. This exists because it caught real mistakes in this tool's predecessor scripts; nothing here removes that safeguard for convenience.
